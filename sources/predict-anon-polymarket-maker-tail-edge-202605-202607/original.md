### 主帖要点

作者分享一类 Polymarket 或类似 sports / crypto 预测市场里的 maker 思路。

核心逻辑：

1. maker 可以赚 LP 奖励和 spread；
2. 最大风险是基本面变化后，被信息更强的 toxic flow 打掉挂单；
3. 规避方向之一是在 `0-5c` 的低概率区间做市；
4. 极端概率区间的价格变化通常比中间概率区间更慢；
5. 如果在 `2c` 附近成交，即使过一段时间后变成 `1c`，绝对损失也有限；
6. 如果单笔最终归零，损失也是几分钱，而一次成功成交可能赚到 `1c` spread。

作者的重点不是“刷 LP 奖励”，而是在低概率、宽 spread、价格变化较慢的市场里捕捉 spread。

### 作者后续澄清

- `2081583193078341789`：LP 不是核心。在作者自己的版本里，LP 只贡献约 `5%` 收入，主要收益来自 spread 优化。
- `2081645738858353118`：很多人过度关注 LP。真正可选的市场反而可能是 spread 很大、没有 LP 或 LP 很少的市场；一周成交一笔也可能覆盖成本，关键是过滤市场。
- `2081575443874955398`：不需要裸买高价侧。可以先买低价侧，有库存后再挂另一侧，避免直接承担 `90c` 归零风险。
- `2081571905568657752`：作者停掉的原因是收益对他而言太小，sports 和 crypto 主策略竞争已经很激烈，需要更多精力。
- `2081593451188273532`：再次强调 LP 只是小收入补充，不是主要收益。
- `2081785316919361600`：如果是纯 LP 双边做到结算，只要事件基本面没有变化，面对他人无法持仓或被诱导退出的场景，持有到结算本身并不一定有问题。

### 评论区风险提示

- 有实践者指出，低价侧一旦成交，未必能以原价退出；事件确定性会随时间增加，`5c -> 4c` 也是 `20%` 损失，LP 奖励未必覆盖。
- 有人认为，接近 `98%` 或低概率尾部时，LP 奖励可能消失，低价区间竞争和订单量也可能很大，资金效率不一定高。
- 有人补充，这类策略以前可能更好做，现在尾端池撤得更快、LP 奖励更低、市场更拥挤。

## 材料二：sports 99.9c尾盘排队策略

- 发布时间：`2026-07-26 22:59`（Asia/Shanghai）

### 背景引用

主帖引用 `DataBasedBets` 对一次 MLB 结算/比分修正事件的描述：

- Giants vs Angels 比赛在延长局出现 walk-off ground-rule double；
- 初始比分显示为 `8-6`，但按 MLB 规则最终应为 `7-6`；
- 多个 over / run line 市场曾因机器人接近确定性买入而被推到接近 `99c`；
- 官方修正后，部分市场方向逆转，Kalshi / Polymarket 上追逐尾盘确定性的账户出现大额亏损。

### 主帖要点

作者表示，自己是这次 Polymarket 上亏得最多的一批人之一，并因此关掉了 sports `99.9c` 策略。

策略机制：

1. Polymarket 有 `tick_size_change` 通知；
2. 通知前只能挂到 `99c`；
3. 通知后可以挂到 `99.9c`；
4. 很多 sports 市场在结果出现后才进入更细 tick；
5. 策略要在结果几乎确定、tick 变细时，抢先挂 `99.9c`。

作者给出的执行要点：

- 当前机制下，越早下单越可能排在队列前面；
- 不能只等 websocket 的 `tick_size_change`，要理解限频并持续尝试下单；
- 可以通过 Polymarket 的 `propose` 机制判断结果是否已被提出；
- 也可以结合 ESPN 等公开体育数据源；
- 为避免错误下单，必须做人工或自建多源校验。

### 作者后续补充

- `2081452317833142314`：过去收益足以覆盖这次损失；策略运行约一年半，只大失败过一次。但现在人变多、收益下降，不值得继续投入盯盘精力。
- `2081407751759221109`：对 sports 尾盘而言，如果多重验证做得好，错误率未必高于 BTC 5m 这类市场。
- `2081404650050539665`：加更多保护规则后仍可能可做；但对作者来说不值得。对部分人而言，每天几十到几百 U 可能仍有吸引力。
- `2081556023022944469`：crypto 5m 提前下单更依赖模型；sports 只在结果确定后做。
- `2081400374586679441`：关于 BTC 5m 尾盘，作者提到如果没有特定延迟优势，容易输给更快或信息更强的对手。

### 评论区风险提示

- 有人指出 BTC 5m 曾出现 Chainlink API 正常但结算异常的情况，因此尾盘确定性并不总可靠。
- 有人认为 sports 更容易出现意外，UFC 等比赛也有争议案例。
- 多位评论者强调这类策略是“赢小亏大”：需要连续正确非常多次，一次错误可能抹掉大量收益。
- 有人认为官方尾盘奖励规则和市场拥挤已经让这类策略不如过去。

## 材料三：用profit/volume估算账户edge

- Tweet ID：`2058553199620243850`
- 链接：`https://x.com/predict_anon/status/2058553199620243850?s=20`
- 发布时间：`2026-05-24 22:18`（Asia/Shanghai）
- 抓取时互动数据：`63` likes，`3` retweets，`9` replies，`0` quotes，`10954` views，`65` bookmarks

### 主帖要点

作者提出一个粗略估算 Polymarket 账户 edge 的方法：

```text
average_EV = profit / volume
```

使用方式：

1. 在 `betmoar` 上查看某个账户的 `profit`；
2. 查看账户的 `volume`；
3. 用二者相除估算平均成交 edge。

作者自己的经验：

- 最好的账户约 `3%`；
- 多数账户约 `1%`；
- 基本符合他对策略收益率的预期。

### 评论区补充

- 有人认为该方法不完全准确，因为 `99c` 和 `50c` 的成交结构不同，单纯 volume 可能无法体现真实 edge。
- 作者回应称，Polymarket 的 volume 是按 share 口径统计，已经有一定权重；尾盘扫单主要靠大量次数，对应高 volume，单笔优势大约也只是 `0.1%-1%`。
- 有评论把这个指标称为 `ROT`，即 return of turnover。
- 其他评论给出自己的账户边际收益水平，如 `0.5%`、`0.12%`、`0.16%` 等。
